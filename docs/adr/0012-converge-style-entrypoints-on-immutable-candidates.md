# 两个风格模板入口汇合到不可变候选生产管线

> 状态：部分被 ADR-0013 取代。`compile/produce` 两入口继续有效；默认直达 OSS 改为先交付审核包，人工通过后进入 OSS。

参考编译和模板自生产分别负责形成统一的模板候选，后续共同执行模板与 Schema 校验、新颖性检查、key 冻结、测试图分配、封面生成、轻量封面检查、OSS 上传、正式地址回填和最终模板包发布。模板自生产未指定数量时默认生产一个候选；批量模式先按基线补缺价值排序，再生产明确 count 指定的前 N 个。

对外生产入口只保留 `compile(reference)` 和 `produce(baseline)`。`compile` 接受对话附件、本地文件和公开 URL，URL 先固化为带来源、时间和哈希的本地证据副本；`produce` 默认读取当前批准基线并补缺生产一个模板，也可以明确 count、分类、缺口方向或 sourceTemplateKey。用户要求编译或自生产“模板包”时，该请求已经包含 OSS 上传授权，两个入口默认运行到正式地址回填和最终模板包；只有明确要求“仅预览”或“暂不上传”时才停在待发布产物。基线批准和真图评测保持为独立阶段。

来源图片指纹只承担来源追溯和重复提醒，不直接决定模板身份。同一任务重试保持原 revision；明确修正已有模板时创建新 revision；明确从同一来源生产另一个独立模板时创建新 key。新 key 使用小写语义化 kebab-case，通过全局重复检查后冻结，首次封面生成开始后不再修改。

每个 package revision 写入独立、不可变的时间目录，不覆盖旧包。当前版本通过有效基线或独立索引指向。该设计允许同一参考图承载多个创作意图，也让两个入口共享同一套交付不变量、幂等规则和失败恢复语义。

每次请求创建持久 runId 和幂等键，统一状态为 `planned → validating → test_image_assigned → cover_generating → cover_checking → awaiting_oss → oss_finalizing → completed/failed`，基础设施异常进入可恢复的 interrupted。批量候选允许受控并行，全局测试图账本原子提交；成功项可以先交付，失败项返回阶段、原因和可恢复性。取消时停止新项目，已经进入封面生成的 revision 保留原测试图绑定。参考分析、轻量封面检查和封面生成分别通过供应方无关 adapter 接入。
