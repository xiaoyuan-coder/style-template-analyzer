# 模板自生产设计与直接视觉评审

本规范约束 `produce` 的候选设计和用户审批。完成标准是每个候选都具有可辨识、可迁移、可追溯的底层机制，并在正式编译、测试图入账和 OSS 上传前淘汰弱方向。

开始候选设计前，必须通过 `style_experience_store.py` 校验 `current.json` 与经验语料摘要一致，并通过 `style_dynamic_baseline.py` 读取全部人工通过项的当前 revision。任一快照缺失、无效或过期时先重建，当前生产不得沿用旧数据继续扩写。

## 1. 用 X × Y × B × C 定义候选

- `X = graphicLanguage`：画面如何绘制，例如硬边平涂、粗轮廓、双色负形、网点漫画、阈值版印。
- `Y = spatialGrammar`：内容如何重组，例如主体提取、模块切分、分镜序列、重复阵列、空间舞台、连续载体。
- `B = contentBinding`：输入如何进入 Y，例如一一保留、可追溯重复、局部放大、特征统计、关系抽象、来源符号化。
- `C = boundaryPolicy`：哪些内容完整收口，哪些结构可以主动触边，哪些识别信息必须保留。

四项都要写清。先读取 `goodcase-after-aesthetics.md` 和 `badcase-learning.md`，再选择候选轨道。视觉统治轨允许 Y 明确写为构图保持或轻量提取，但 X 必须明显改变全部像素并形成产品级签名；关系发明轨要求 Y 明显改变内容关系。B 必须让每个派生元素回溯到用户输入；C 必须区分主动构图与生成异常。配色替换、颗粒、纸纹、金属感、线宽微调、外加边框或普通背景不单独算 Y。

默认印制模板把材质作为辅助表现。只有用户明确需要实体材料形态且适用场景足够广时，才把黏土、金属、钩织或压印设为主 X。印刷语言可以使用网点、排线和有限色阶。

### 1.1 表现模式与抽象转译卡

每个候选在 X/Y/B/C 之外声明一项 `representationMode`：

- `figurative-anchor`：具象主体承担主要识别，结构与成像负责增益。
- `semi-abstract`：保留少量身份锚点，其余内容转成轮廓、色场、节奏或关系结构。
- `abstract-dominant`：数量、方向、比例、间距、接触、包含、重叠、拓扑或正负形承担主要阅读，具象锚点默认不超过有效图案面积的 35%；超过时写出来源识别理由。

关系发明轨在生成 prompt 前完成一张抽象转译卡：

- `abstractionSource`：输入中可观察、可比较或可追溯的来源信号。
- `abstractionOperator`：计数、聚类、压缩、镜像、交错、排序、尺度映射、方向场、拓扑保持、正负形交换或其他明确算子。
- `abstractOutput`：算子落成的点、线、面、场、间隔、路径、阵列或空隙结构。
- `figurativeBudget`：需要保留的最小身份锚点、占比与允许删减的写实细节。

抽象层完成时，即使临时把人脸、毛发、摄影光影和写实背景替换成单色轮廓，观众仍能从大形、节奏或空间关系读出模板主动作。只有浅色背景、柔和水彩、装饰曲线、纸纹或少量几何形时，继续视为具象插画。

批次默认满足以下表现模式配额：

- `semi-abstract + abstract-dominant` 至少占 40%。
- `abstract-dominant` 至少占 20%。
- `figurative-anchor` 最多占 60%。
- 五至六个候选至少覆盖三个抽象算子家族；十二个候选至少覆盖四个。

抽象主导 prompt 先描述大形、关系算子和留白，再补充最小 `recognitionAnchors`。身份保留聚焦轮廓、姿态、关键配色、关系物或一个局部特征；完整写实脸、完整毛发和摄影级环境只有在来源价值确实依赖它们时进入 prompt。

## 2. 创意母题与模板实现分层

自生产先读取总库 `../../05-风格化模板生产/01-风格参考素材/自生产创意库/creative-inspiration-library.json`。这里的条目是高层创意母题：一种观察方式、关系算子或内容重组思路，不绑定模板 key、固定画风、固定版式和单次人工状态。

先写 `sourceAdvantage`，再按条目的 `fitSignals` 选择一个主创意，用 `inspirationPrompts` 和 `mutationAxes` 至少推演两种不同载体或阅读路径。完成标准是去掉案例画风、布局和物象后，仍能说明创意怎样改变观看方式。

选定主创意后，再读取相邻 `../../05-风格化模板生产/01-风格参考素材/模板实现案例库/template-idea-realization-case-library.json`。实现案例保存具体 key、X/Y/B/C、预览图和人工状态，只用于重复检查、边界校验和经验学习。新候选需要写出相对历史案例改变的载体、内容落点或阅读路径。单个实现案例被驳回，只约束该实现；上层创意可以通过新的载体和边界策略继续探索。

GoodCase 和 BadCase继续保存人工验收证据。创意库负责发散，实现案例库负责追溯，GoodCase/BadCase负责学习。

## 3. 从灵感提取机制

读取 Skill、仓库或参考设计时，先记录四项：内容落点、关系重组、来源绑定、边界行为。复用观察到的机制，重新发明载体；固定外壳、案例物象、通用装饰和界面部件不随机制迁移。

例：从“双窗大小反差”保留尺度与密度关系，可改写成双岛、双层色场或远近双景；只有用户明确要求界面时才保留窗框。完成标准是去掉来源的配色、材质和外壳后，候选的 Y 与 B 仍能独立描述。

## 4. Y 家族与批次门槛

优先从以下家族选取并继续发明：

1. 全幅保留：保持原构图，整体替换成像语言。
2. 主体提取：贴画、徽章、剪影或模切主体。
3. 模块切分：非等分片块、负形嵌套或异形锚点。
4. 分镜序列：景别、尺度、局部或阶段递进。
5. 重复阵列：网格、星群、放射或非均匀重复。
6. 具象—抽象双层：主体与数量、方向、重叠、间距的双重编码。
7. 空间舞台：前中后景、侧翼、场片或等距微缩空间。
8. 连续载体：折页、长卷、环路、关系带或锚点续景。
9. 界面容器：CRT、档案、图录或说明页；普通印制生产默认不选。

提出候选前回答：内容放在哪里；关系如何被 Y 重组；B 如何保持来源归属；去掉 X 后 Y 能否从缩略图识别；更换人物、物件或场景后是否仍成立。

- 每个候选明确一项主 X、主 Y、B 和 C。
- 自生产批次默认让关系发明轨占 60%–70%，视觉统治轨占 30%–40%。
- 六个候选至少覆盖三个 Y 家族；五个候选仍至少覆盖三个。
- 同一 Y 家族最多保留两个，且两者通过不同的内容关系成立。
- CRT、街机和窗口只算一个界面家族。
- 只有 X、Y 弱成普通插画或沿用同一结构骨架换皮的候选，在付费生成前淘汰。

### 4.1 装饰母题预算与审美词解耦

花、叶、心形、星点、云朵、闪光和丝带属于高频通用母题。它们可以承担来源内容或结构功能；作为气氛填充时，同一母题家族每六个候选最多出现一次。来源本身不可缺少的花、叶或云可以保留一次，继续扩散成背景花瓣、花环、叶影或装饰散点时计入预算。

每个次级元素在草图阶段标注两项：`sourceOrigin` 与 `structuralFunction`。能回溯输入并承担方向、计数、分层、连接、尺度、节奏或边界功能的元素进入候选；只有“更可爱、更文艺、更清新”的气氛作用时，改用来源比例、留白、密度、错位、停顿或色场关系完成审美表达。

审美词按可迁移机制展开：

- 可爱：比例反差、笨拙节奏、停顿、错位、单一夸张特征或角色与物件的反常关系。
- 文艺：删减、片段、留白、阅读节奏、克制色阶、材质痕迹或不完整叙事。
- 清新：高明度、低密度、透明层、轻色场、开放边界和稳定呼吸空间。
- 创意：来源信号经过明确算子后形成新的观看方式，抽象结构承担主要记忆点。

批次审计同时统计通用母题和写实占比。通用装饰反复出现、抽象模式配额不足或多张候选都由完整写实主体加轻背景装饰构成时，整批返回重新发明阶段。

## 5. 语义完整性与主动裁切

按载体类型判断完整性：

- 独立 `artwork`、`emblem` 和贴纸默认生成完整图案或闭合形状，外轮廓连续，四周保留约 8%–12% 安全边距。
- 嵌套结构中的内层主体保持独立、完整、可辨识。
- `panel-sequence` 可使用景别放大、满版延伸和分格边缘裁切；主体身份、面部或核心识别特征、关键关系仍需清晰。
- `pattern`、抽象关系带和连续背景可让圆环、弧线、色块或纹理主动跨越画布边缘，以形成连续节奏。
- 主动裁切需要可说明的构图功能：景别推进、满版连续、节奏延伸或尺度强调。

以下情况判为异常裁切并 retry：主体在无构图理由时拦腰截断；面部或关键识别部位丢失；关系链被随机吞没；边缘残片无法回溯来源；结构载体像从更大画面中误裁一段。第二次仍失败则拒绝该 revision。

普通印制模板使用纯图案结构。外框、放大镜小窗、连接线、定位点和分析标注只在用户明确要求图鉴、档案、分析或说明书效果时进入 `templateConstants`。

## 6. 审美非退化与结构有效性

先守住原图价值，再判断机制新颖性。候选处理后至少维持输入的主体魅力、可读性、比例、构图重心和情绪；主体变怪、画面变丑或信息更混乱时直接淘汰，额外效果和复杂度不能抵消审美退化。

逐项执行以下测试：

- **信息增量测试**：分镜、并列和重复实例必须在景别、视角、时序、动作、局部信息或抽象统计上形成明确差异。相邻分镜变化很小，或直接并列同一完整人物、宠物和角色，只会增加数量，不形成有效 Y。
- **可识别主体重复测试**：人物、宠物和角色默认保留一个完整主锚点；第二个实例优先承担局部放大、尺度对照、前后状态或关系回应。图案化物件可进入阵列，但重复必须建立节奏、密度或分类关系，避免把同一有生命主体机械复制成群。
- **去结构测试**：临时移除外框、装饰边、几何蒙版或异形轮廓。若内容落点、阅读顺序和主体关系基本不变，该元素只是装饰，不计为 Y。
- **变形预算测试**：形状可以概括、放大和轻度重排；外轮廓、关键识别特征和自然比例仍需稳定。扭曲复杂度开始抢夺主体注意力，或让用户先看到处理痕迹时，降低变形强度。
- **构图连续测试**：左右、上下或具象—抽象区域需要通过重叠、延续、呼应、共同方向或层级关系组成一张图。清楚的硬分割只有在表达对照、时间或因果关系时成立。
- **媒介关系测试**：允许混合媒介，摄影、插画、版印、几何抽象或线稿可以共同出现。为每种媒介分配主体、环境、证据、细节或隐喻等角色，并用来源色形、共同边缘、遮挡、运动方向、渐变过渡或共享纹理建立视觉桥。只有媒介不同且彼此没有作用的并置判为生硬割裂。
- **抽象证据测试**：逐项核对 `abstractionSource → abstractionOperator → abstractOutput`。抽象输出需要显影一项原图关系；只能解释为气氛、画风或装饰时，降低 `representationMode` 或重新设计。
- **写实惯性测试**：把完整写实主体替换为最小识别锚点。主动作仍成立时保留抽象方案；画面随主体消失时，当前 Y 仍依赖写实插画，需要增加关系结构或改走视觉统治轨。
- **母题预算测试**：统计本批通用花叶、心形、星点、云朵、闪光和丝带。超过预算的候选优先改用来源数量、方向、比例、间距、拓扑或正负形完成同一情绪。

“一个完整主锚点 + 一个来源明确的放大细节”是可用的尺度关系；放大部分需要补充观察价值，并与主锚点共享视觉语言或空间联系。它不等于重复两个完整主体。

## 7. 直接生产再评审

用户需要判断效果时直接生成候选图；文字示意只作内部推演。按以下顺序评审：

1. **after 第一眼吸引力**：缩略图是否有清楚视觉中心、节奏和记忆点。
2. **来源价值保留**：输入最有魅力的姿态、关系、瞬间或构图优势是否仍在。
3. **X 视觉统治力**：图形语言是否覆盖整张图并形成产品级辨识度。
4. **Y 内容适配**：关系发明轨的空间语法是否来自输入并带来阅读增益；视觉统治轨的构图保持是否守住原图优势。
5. **B/C 与结构有效性**：派生是否可回溯，主动裁切是否有功能，框、分割和媒介对比是否真正组织内容。
6. **印制闭合度**：缩小后是否仍可读，边界和主体占比是否稳定。
7. **泛化**：更换输入类别后是否仍形成同一模板。

按 `goodcase-after-aesthetics.md` 的 100 分表打分。总分低于 80，或 after 第一眼吸引力、来源价值保留未达到各自权重的 80%，立即淘汰或重做；新颖性和复杂度不能补偿难看的 after。

测试图审美质量差、主体状态怪异或干扰结构判断时，立即更换并退出当前 ready 选择；保留审查证据。模板结构合格不能抵消难看的封面。

### 批次明亮度与开放感

每批在生成前声明视觉预算，并在接触表复核：

- 高调明亮候选不少于 35%；
- 开放留白或低信息呼吸区候选不少于 30%；
- 大面积近黑背景候选不超过 20%，同一行接触表避免连续出现；
- 冷、暖、中性色及高低饱和组合均需出现；
- `figurative-anchor`、`semi-abstract`、`abstract-dominant` 都有代表项；
- 解构、重构、路径、负形、尺度派生和媒介统治至少覆盖三类，材质替换不单独计入结构多样性。

预算服务批次方向，用户对每张 After 的选择保持最终权威。用户反馈整批沉闷时，下一批先提高高调、留白和暖亮色占比，再补充新题材。

## 8. 批准与编译

- 保存批准序号、工作标题、X/Y/B/C、主动裁切说明和淘汰项；用户明确指定的 GoodCase 单独标记，用户明确不通过的 revision 同步写入 BadCase。
- 把用户选中的图像 revision 作为批准权威。附件可能来自首版、retry、replacement、总览副本或总览外候选；对全部候选图做解码后像素等价匹配，保存附件 SHA、解码像素 SHA、匹配方式、`index`、`key`、`selectedCover`、`selectedCoverSha256`、`selectedCoverPixelSha256` 和 `testAssetId`。
- 同一 key 出现多张效果图时，每张图是独立的视觉 revision。总览选中状态、文件名顺序和候选 key 均不能代替像素匹配。
- 用 `scripts/build_style_badcase_corpus.py` 幂等更新总库 BadCase 语料库。只收录用户明确拒绝的 revision；待审核、未表态、生成失败和只有自动门禁结论的候选继续保留为批次证据。
- 批准前只交付候选效果；数量目标或“模板包”字样不能跳过审批。
- 所有合格候选先编译审核包并预留唯一测试图；淘汰项根据人工 `reject` 释放测试图，不进入 OSS 最终化。
- 人工 `pass` 同时冻结批准名单、封面 SHA 和 prompt SHA，完成 GoodCase 与当前经验快照更新后进入 OSS 最终化；`pending` 持续占用当前测试图。
- 用户纠正设计判断时，用新 approval revision 覆盖当前决策，保留旧轮次作为历史证据。
- 收到最终化授权后生成批准专用编译规格。对总览外候选、被 retry 替换的首版和同 key 共享规格的不同视觉 revision，重新核对选中图的 X/Y/B/C。当选中版与共享规格的视觉机制有差异时，写入版本专属编译覆盖，并记录 `selectedVariant`、`variantNote`、源图 SHA、效果合同 SHA、实际生成 Prompt SHA 和最终 Prompt SHA。
- 编译时把冻结后的 X、Y、B、C 和越权边界写进 `promptTemplate`。审批图只是离线设计证据，运行时图片数组仍只含用户上传图。
- 在 OSS 之前运行 `python scripts/style_workflow_cli.py validate-approved-variants <approval.json> <approved-compilation-spec.json>`。通过条件是：批准数量和 key 集合一致；附件与 `selectedCover` 的解码像素一致；cover 文件 SHA 正确；实际生成 Prompt SHA 等于最终 Prompt SHA；源图与效果合同 SHA 完整；`testAssetId` 在当前交付集内唯一。
- 最终包继续执行基线新颖性、唯一测试图、OSS 回填和严格双文件校验。

## 9. 候选审计清单

- [ ] X 可迁移，材质没有无意占据主轴。
- [ ] 已从独立创意库选择主创意，并通过启发问题与变体轴推演至少两种不同载体或阅读路径。
